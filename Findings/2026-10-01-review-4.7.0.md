# 4.7.0 review: defects, fixes, measurements (2026-10-01)

A full-codebase review of 4.6.13 found that most user-visible failures came from two
patterns: broad `except Exception` blocks that hid errors (464 of them, 149 bare `pass`),
and effort spent on rare dynamic-import cases while common static imports were unresolved.

## Defects fixed (each has a test in `tests/test_regressions_4_7.py`)

| Area | Defect | Fix |
|---|---|---|
| Root | A missing `project_root` silently fell back to the cwd and wrote state there | `paths.resolve_root` raises `ProjectRootError`; every entry point returns it as an error |
| Paths | `record_change`/`mark_green`/`record_deletion` normalized paths three different ways; absolute paths created duplicate health rows and stuck pending items; `mark_green` accepted nonexistent files | `paths.to_rel` everywhere; `mark_green` is one load/save and refuses missing paths |
| Health | Keys starting `tmp/`, `home/`, `Users/`, `var/` were treated as absolute and pruned | Lexical containment check (`paths.is_under`) |
| Pending | Removing `a.py` also removed `data.py` (substring match) | Exact path match on the bullet's path |
| Pending | check-changes added "auto-detected" items, then its own scope-prune deleted them | Scope prune no longer drops auto-detected items |
| Watch | Non-source monitored files (README, run.md, *.sh) were never checked | Explicit monitored files of any type are watched |
| Preflight | `prepare_edit` read `resolved_path` but the cache stores `resolved` → always None | Reads the cache key; dependents from the indexed edge table |
| Python parser | Absolute imports (`from pkg import x`, `import pkg.mod`) never resolved | `ast`-based parser; project/package/`src` roots; submodule edges; guarded imports conditional |
| JS parser | Imports in comments/strings were edges; overlapping patterns duplicated edges; `import()` with a literal was "static"; packages were tagged as barrels | Lexer masks comments + records string spans; specifier-position dedupe; `dynamic_type="literal"`; externals never barrels |
| CDIA | Any `if`/`for`/`const x = …;`/type annotation in the 1,200 chars before an import marked it conditional | Scope builder finds only *enclosing* guards (braces for JS, indentation for Python) |
| Resolution | Unresolved relative imports reported the attempted path as resolved (phantom graph nodes) | `resolved_file=None`, attempted path kept in metadata |
| Barrels | Relative-import bugs (`from .. import import_cache` in `parsers/bree/`) meant the persistent barrel cache never loaded; `_brc_canonical` import also failed silently | Correct imports; barrel cache persists; invalidation uses exact canonical keys (basename/substring matching removed) |
| Summaries | `_acs_summary` and `_resolution_diagnostics` were never recomputed once stored; `_graph_integrity` was written only by an MCP *read* tool and went stale | Recomputed every update-maps; integrity derived on read |
| Cache | SQLite save failure silently wrote JSON that was never read again; dependents required loading the whole cache | Errors propagate; `edges(src,dst)` table with indexes; nanosecond mtimes so unchanged files are never hashed |
| Streaming | `update-maps --stream` parsed files but never persisted the map | Streams progress from the real pipeline (worker thread) |
| Locking | Re-entrancy was per process, so a second MCP thread could enter while a timed-out call held the lock | Re-entrancy per thread |
| Journal | Write failures were swallowed; MCP retries after a timeout double-recorded | Writes raise; identical retries within 120 s are de-duplicated |
| CLI/shell | Python CLI fell back to a 923-line shell script that re-implemented record-change/mark-green (md only) and called a nonexistent `python -m wikifier.health`; `.ps1` used the script dir as the project | All commands in Python (`argparse`); launchers are 15-line wrappers |
| CLI | Any `--target` command copied `index.html` into the target | Only `init` copies the dashboard |
| MCP | Every tool retried through the shell on any exception; `update_maps` reported success unconditionally; `health` text called a nonexistent function; journal resource used the wrong path | Thin adapter over `wikifier.api`, no subprocess, honest results |
| Daemon | Metrics used `from . import health` (the function); `stop` sent SIGKILL; the systemd unit had no project root | Health module, SIGTERM + grace, unit pins `WorkingDirectory`/`WIKIFIER_PROJECT_ROOT` |
| Healing | Stub statistics checked the status field for "Initial stub" → always 0 | Uses the map-first stub classifier |

## Structure

- `health_impl.py` (2,597 lines) → `health_pkg/{store,pending,freshness,scope,summary,readiness,healing}.py`.
- `cache/_core.py` (2,422 lines) → `cache/{graph,cycles,acs,barrel,diagnostics}.py`; streaming moved to `wikifier/streaming.py` (it depends on the API layer; keeping it in `cache` created an import cycle).
- New: `paths.py` (root/path normalization), `journal.py`, `cache_store` edge table.
- Broad exception handlers: 464 → 80 (17 are deliberate API boundaries; most of the rest guard heuristic analysis of arbitrary user code). Silent `pass`: 149 → 29. Package size: 25.7k → 20.8k lines.
- Process labels ("Wave 3", "Gap #1", …) removed from code comments and agent-facing strings.
