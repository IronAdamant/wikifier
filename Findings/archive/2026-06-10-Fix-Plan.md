# Fix Plan — 2026-06-10 dogfood findings

Source findings: `Findings/2026-06-10-Dogfood-Refactor-Validation.md` (W/R/S/E numbering
reused here). Ordered by dependency and leverage: regression net first, then the two
shared roots (BREE save storm, shell map builder), then the real python-primary pipeline,
then correctness/UX cleanups, then full re-validation.

## Phase 0 — Minimal regression net (enables everything else) [E2]

Stdlib-only `unittest` suite under `tests/` (zero-dep rule preserved; `python -m unittest
discover tests` documented as the verification command):
- `test_parsers.py`: Python + JS edge contract on small fixtures (static/relative/dynamic
  imports, one barrel chain); asserts canonical fields (relative src, real booleans).
- `test_import_cache.py`: canonical schema round-trip, reserved `_` keys, reverse deps,
  cycles on a 3-node SCC fixture.
- `test_barrel_invalidation.py`: consumer → barrel → leaf fixture; touch barrel; assert
  importer marked stale (this is the E1 repro).
- `test_library_generation.py`: library.md generated from a seeded cache contains the
  Mermaid graph + edges, and generation is atomic (no truncate-then-fail).
- `test_health.py`: record-change → yellow, mark-green → green, exclude patterns.

## Phase 1 — Stop the bleeding in wikifier.sh [W3, W4, W5]

1. **W3**: `node_dependents` is dead-from-birth (never populated anywhere in history).
   Remove the `dep_count` thick-arrow branch entirely (lines ~716–727) — it can never
   fire — instead of declaring an always-empty array.
2. **W4**: add `import os` to the reverse-deps `python3 -c` block (~line 1197). Route its
   stderr to the staging debug log instead of `/dev/null`.
3. **W5**: build library.md to `library.md.tmp.$$` and `mv` into place only on success;
   on failure keep the previous artifact and print a real error.
4. Sync root → packaged copy; both copies must stay byte-identical (now checked by a test
   in Phase 0 if cheap, else by the release script).

## Phase 2 — Kill the BREE cache-save storm [S5 → fixes W6 too]

`bree.expand_chain` (and the BarrelResolutionCache write path) must stop calling
`import_cache.save_cache` per chain:
- Accumulate chain resolutions in the in-memory cache dict and set a `dirty` flag;
  persist **once** at the end of a parse run (parser entry already loads/saves the cache
  at well-defined points) — or expose `flush()` called by `parse_javascript_imports`
  before return.
- Acceptance: in-process JS parse ≤ ~50ms/file median on the Babylon 300-file sample
  (from 963ms/file); sh path on the 17-file scratch copy well under 30s (from 3m19s).

## Phase 3 — Make `--python-primary` a real full pipeline [W7, S1, W10]

In `cli.run_full_update`:
1. Remove the `min(20, dirty)` cap: parse **all** dirty files (Python ~1ms/file; JS
   acceptable after Phase 2). Keep optional `max_files`/`directory` as *explicit* scoping
   with the cap reported in the result (no silent caps).
2. Persist through the **canonical per-file schema** via `import_cache` helpers (kill the
   top-level `resolved_pairs` blob; project-relative `src`; real booleans). [W10]
3. After persist: compute and store `_reverse_dependencies`, `_cycles` (+ analyses) and
   `_acs_summary` using the existing import_cache functions.
4. **Generate library.md in pure Python** (new `wikifier/library.py`, ported from the sh
   mermaid builder: graph + dependency table + cycles + unresolved/low-confidence
   sections; atomic write). The sh builder remains as fallback.
5. Always write `import_cache.json` even when 0 files are parseable, and include
   `parseable_files` in the result so redox-type projects get an honest report. [S1]
6. Result dict gains `files_parsed` (actual) alongside `files_to_reparse` (detected).
