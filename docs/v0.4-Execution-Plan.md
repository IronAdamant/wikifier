## 1. Vision & Strategic Goals

Wikifier is an **agent-first, zero-dependency codebase memory and documentation system** designed to act as a **low-ambiguity librarian** for LLMs and agents.

### Core Vision

- Enable agents (and humans) to maintain deep, structured, long-term understanding of codebases across many sessions and different models.
- Significantly reduce token usage and context loss by providing high-quality, queryable, trustworthy information.
- Scale gracefully from small projects to massive monorepos.
- Prioritize **accuracy** (especially minimal false negatives) and **trustworthiness** so agents can treat the output as a reliable source of truth.

The system must support **agent-to-agent collaboration** — different agents should be able to read and contribute to the same structured knowledge base without constant re-validation.

---

## 2. Definition of "Production-Useful" for v0.4

Based on current requirements, v0.4 will be considered **production-useful** when the following hold:

- **Minimal False Negatives**: When a real dependency (or reverse dependency) exists, the system finds it in the large majority of cases.
- **High Trustworthiness**: Agents can rely on `library.md` and future query interfaces as a primary source of truth for dependency and codebase questions, with only well-documented exceptions.
- **Scalability**: The system remains usable and reasonably performant on large-to-massive monorepos (tens of thousands of files).
- **Low Ambiguity**: The data returned is structured and explicit enough that agents do not have to do heavy guesswork or re-parsing.
- **Bidirectional Value**: Both forward dependencies (“what does this file import?”) and reverse dependencies (“what depends on this file?”) are available and useful.

## 6. Risks & Mitigations

- **Risk**: Over-investing in perfect accuracy at the cost of shipping.
  - **Mitigation**: Define clear “good enough for production” criteria and stop when they are met.
- **Risk**: Shell script complexity becoming a bottleneck.
  - **Mitigation**: Be willing to invest more in the Python side of the tool.
- **Risk**: Losing momentum if M2 takes too long.
  - **Mitigation**: Ship meaningful intermediate value (e.g., strong Python + edges) even if not everything is finished.
